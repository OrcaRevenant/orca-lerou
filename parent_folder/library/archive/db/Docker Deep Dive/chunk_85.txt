Things are a bit different in the container model.
When the server is powered on, your chosen OS boots. In the Docker world this
can be Linux, or a modern version of Windows that has support for the container
primitives in its kernel. As per the VM model, the OS claims all hardware
resources. On top of the OS we install a container engine such as Docker. The
container engine then takes OS resources such as the process tree, the
filesystem, and the network stack, and carves them up into secure isolated
constructs called containers. Each container looks smells and feels just like a
real OS. Inside of each container we can run an application. Like before, we’re
assuming a single physical server with 4 applications. Therefore we’d carve out
4 containers and run a single application inside of each as shown in Figure 7.3.
